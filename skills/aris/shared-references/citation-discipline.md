# Citation Discipline

Use `pi-literature-search` from `pi-literature-review` for academic paper discovery. The tool reply is a short digest and an HTML report path; read the same-basename JSON sidecar at the actual output location. Confirm top-level `query`, `generated`, `sources_used`, `results[]`, and `dropped[]`. For each cited paper retain its JSON path, record location or ID, `title`, `authors`, `year`, `doi` or `arxiv_id`, `sources[]` (or the raw `source`), and `verified` status.

Only a `results[]` record with `verified: true` and a DOI or arXiv ID is a **verified bibliographic citation**. That status means the identifier resolved; it does not validate the paper's findings, peer-review status, or a research gap. Read the saved abstract for substantive claims. For details beyond the abstract, use `/lit-selection` and `/lit-synthesis` on user-selected full texts and cite the relevant passage or page. A `dropped[].record`, unverified result, or paper found with `pi-web-access` is a lead until a new verified literature-search record supports it.

Record query variants, source failures and skips, abstract lookup failures, generated date, and search limits near a novelty or coverage claim. `group: on_target` is a lexical tag, not a scientific verdict. Never infer that no prior work exists from an empty result. Do not invent titles, authors, identifiers, venues, or result claims. Preserve the exact identifier and its source JSON when importing into the wiki.
